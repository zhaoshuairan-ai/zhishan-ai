# 比赛演示流程与 5 分钟讲稿

> 目标：在 5 分钟内让评委看到「真实 OCR → 人工校正 → AI 解读 → 标签核查 → 可追溯来源 → 跨设备记录 → 报告与扫码」，
> 并让评委相信这不是一个静态页面或套壳演示。

---

- [ ] `start.bat` 能一次启动成功（先跑一遍完整流程）
- [ ] 真实图片测试：准备 3 张清晰的食品标签照片（正面 / 配料表 + 营养表 / 日期喷码各 1 张）
- [ ] 若使用公网地址：`prod_smoke_test.py --base-url https://...` 全部通过
- [ ] 二维码已生成并**用手机实际扫过**
- [ ] 若配置了 AI Key：确认「设置与帮助」显示「已配置」，并跑通一次 AI 解读
- [ ] 历史记录中保留 2-3 条真实记录（不要全是演示数据）
- [ ] 报告排版已确认：可直接打开 `docs/sample-report.pdf` 查看自动生成的样例
- [ ] 准备离线备用方案（见第五节）

- [ ] 后端与前端已启动，首页能打开

- [ ] 浏览器标签页顺序：首页 → 上传 → 结果 → 报告 → 知识库
- [ ] 手机屏幕亮度调高，准备好扫码

## 三、5 分钟逐字讲稿

### 0:00-0:30 开场（首页）

> 各位评委老师好，我带来的作品是《智膳 AI》——一个面向家庭与个人的全场景健康膳食管家。
>
> 我们每天都会看到配料表，但大多数人看不懂：这些添加剂是做什么的？营养成分表里的 NRV% 是什么意思？保质期到底怎么算？
>
> 这个作品做的事情不止是读懂标签：**拍一张包装或餐盘照片，它帮你识别、解释，再结合健康画像、库存、天气与预算，生成可执行的三餐方案；关键结论都可以追溯和复核。**

### 0:30-1:20 上传与真实 OCR

>（打开「开始检测」，拖入准备好的标签照片）
>
> 上传之后系统会先做文字识别。这里要特别说明：**这是真实的 OCR，不是预置的示例文字**。
> 我们用的是本地离线的中文 OCR 引擎，不需要联网、不需要 API Key，识别一页标签大概 3 到 8 秒。
>
>（等待结果）
>
> 你可以看到它把内容拆成了食品名称、配料表、营养成分表、生产日期、保质期等 11 个字段。
> 注意这里有个黄色标签——「低置信度」。也就是说系统自己知道哪个字段可能识别错了，而不是假装全对。

### 1:20-1:50 人工校正

>（修改“食品名称”或某个错字，点保存）
>
> 识别错了可以逐字改。**原始 OCR 文本不会被覆盖**，校正文本单独保存，所以整个分析过程是可追溯的。
> 这也体现了我们对 AI 的态度：AI 负责提效，人负责最终确认。

### 1:50-2:40 AI 配料解读

>（滚到配料分析）
>
> 系统把配料表拆成一项一项，然后解释每一种成分的常见用途。
> 每一条解释都有两个标签：**依据来源**和**可信度**。来自知识库的会标「知识库依据」，并给出编号，比如 K6 三氯蔗糖，点过去能看到完整条目和来源。
>
> 这里要强调我们的底线：**食品添加剂只解释用途，不判定有毒或有害**。
> 添加剂是否合规，取决于品种、使用范围和使用量，这需要检测和监管数据，不是看配料表就能得出的。

### 2:40-3:20 营养可视化

>（滚到营养区）
>
> 营养成分表会被解析成结构化数据，保留原始数值和单位。
> 左边是核心营养素的 NRV% —— 让你知道吃一份大概占一天参考值的多少；右边是能量来源估算，蛋白质、脂肪、碳水化合物各贡献多少能量。
>
> 如果某个项目标签上没有，这里会明确写「未识别」——**系统不会编造数值**，这是我们在设计上最重要的一条原则。

### 3:20-4:00 标签辅助核查

>（滚到核查区，点开一条「依据与来源」）
>
> 核查部分用的是集中管理的规则库，一共 24 条规则，每条都有版本号、依据说明和「待确认事项」。
> 结论只有三档：未发现明显问题、需要进一步核实、发现疑似问题。
>
>（展开一条）
>
> 比如这里它会说：这条日期推算的依据是「生产日期 + 保质期」，并提醒你「若包装上直接印有到期日期，以实物为准」。
> 我们刻意避免两种表述：一是「图片没拍到」不等于「包装上没有」；二是「规则没发现问题」不等于「食品一定安全合规」。

### 4:00-4:30 跨设备与报告

>（拿起手机，展示同一账号的历史记录）
>
> 这是同一套后端服务、同一个数据库。我在电脑上创建的记录，手机上登录同一账号就能看到，刷新、重启服务都不会丢。
>
>（电脑打开报告页，按 Ctrl+P 展示打印预览）
>
> 报告包含原始识别文本、校正文本、配料解释、营养图表、核查结论、资料来源和免责声明，可以直接打印或另存为 PDF。

### 4:30-5:00 收尾

> 最后说明一下能力边界：我们只读取包装上可见的文字，**不做实验检测**，无法判断微生物、农残、重金属这些指标，也不构成合规认定。
>
> 技术上，它是 Vue 3 + Flask 的前后端分离架构，本地 OCR 与知识库规则模式保证在没有任何 API Key 的情况下也能完整演示，配置大模型后会升级为 AI 解读，并且全程标注当前模式。
>
> 如果评委老师想看，桌面上有二维码，手机扫码就能打开同一个站点。谢谢！

## 四、演示动线小技巧

- **提前准备两张图**：一张字段完整（展示全流程），一张故意缺字段或日期异常（展示核查与“未识别”）。
- **不要现场拍模糊照片**：识别失败会打断节奏；把失败情况留到“回答问题”环节说明。
- **低置信度是加分项**：主动指出「系统知道自己可能错」，比声称 100% 准确更可信。
- **模式横幅要点出来**：如果没有配置 Key，就主动说“这是基础规则模式，界面有标注”，诚实反而得分。
- **手机演示只做一件事**：打开历史记录证明跨设备同步，不要在手机上走完整流程（耗时且容易出错）。
- **报告用打印预览而不是真的打印**，省时间且能一次性展示排版。

## 五、异常兜底方案

| 突发情况 | 应对 |
| --- | --- |
| 现场网络断开 | 本地 OCR + 规则模式完全离线可用；先演示本地流程 |
| OCR 识别失败（图片太糊） | 直接点“手动填写配料表”，继续演示后续能力；说明“识别是辅助，校正才是保障” |
| 识别到了但字段被截断/杂乱 | 在校正页点「重新识别」重跑一次 OCR；仍不理想就手动补关键字段 |
| 大模型 API 报错 | 系统自动降级规则模式，界面会提示；顺势讲“我们设计了降级链路” |
| 后端没起来 | 重新运行 `start.bat`；或改用 `start_prod.bat` 单服务模式（8000 端口） |
| 手机连不上电脑 | 改用公网地址；或提前把手机截图/录屏放进 PPT 作为备份 |
| 公网隧道失效 | 立刻切回局域网地址演示；二维码环节改为展示提前录好的扫码视频 |
| 时间被压缩到 3 分钟 | 只演示：上传 → OCR 结果（指出低置信度）→ 配料解释（指出来源）→ 核查三档 → 报告 |

> 彩排提示：没有真实 Key 时，可用 `scripts/mock_llm_server.py` 预览「大模型模式」的界面与交互。
> **正式演示时不要把模拟服务的输出当成真实模型结果**；如果现场用模拟服务，请主动说明这是本地模拟环境。

## 六、评委常见提问与参考回答

**Q1：这和直接问 ChatGPT 有什么区别？**
> 三点不同：一是有真实 OCR 链路，能从图片得到结构化字段并标出置信度；二是知识库检索增强，每条解释都能回溯到条目与来源；三是有独立的规则核查引擎，检查字段完整性、日期逻辑、单位与数值一致性，这些是大模型单独做不到的。

**Q2：AI 会不会胡说？**
> 会，所以我们做了四层控制：提示词约束、Pydantic 结构校验、幻觉过滤（不在配料表里的成分与对不上知识库的引用会被丢弃）、以及把不确定内容标为「未验证/待确认」。界面和报告都会显示当前是 AI 模式还是规则模式。

**Q3：你们能判断食品是否安全吗？**
> 不能，我们也明确不做这个判断。平台只读取标签可见文字，无法检测微生物、农残、重金属；添加剂也只解释用途，不做安全性结论。

**Q4：为什么用 SQLite，能支撑真实用户吗？**
> 比赛阶段单机演示 SQLite 完全够用，且零配置、便于评委复现。模型层是 SQLAlchemy，换 PostgreSQL 只需要改连接串并重新初始化；正式多实例部署我们计划加 Alembic 迁移与对象存储。

**Q5：识别准确率多少？**
> 我们没有宣称固定准确率。本地 OCR 对清晰、平整、无反光的标签识别率较高；我们更看重的是**把不确定性暴露出来**——低置信度字段会被高亮，用户可以校正，原始文本保留，所以结果始终可核对。

**Q6：数据存在哪里？手机和电脑怎么共享？**
> 数据库与图片都在后端，前端只通过 API 读写。同一个账号在手机和电脑登录，读的是同一个数据库，所以看到同一份记录。我们现场可以验证。

**Q7：隐私和权限怎么处理？**
> 密码用 scrypt 哈希存储，令牌只存 SHA-256，记录按账号隔离，越权访问统一返回 404；图片通过带鉴权头的请求获取，不把令牌放在 URL 里。删除记录会同时删除数据库数据与磁盘文件。

**Q8：为什么不用现成的 OCR 云服务？**
> 可以接，系统已经预留了视觉模型驱动（OpenAI 兼容协议）。默认用本地 OCR 是为了让评委在任何网络环境下都能复现，且不产生费用。

**Q9：这个项目的创新点是什么？**
> 四段式闭环（识别—校正—解读—核查）、可追溯的证据链（知识库编号 + 规则版本）、审慎的三档结论体系、以及“零 Key 可运行、模式全程标注”的诚实设计。

**Q10：后续怎么落地？**
> 近期做多图合并（正面+配料+营养+喷码）、知识库后台与权威资料导入、报告分享链接与 PDF 服务端生成；中期迁移 PostgreSQL、接入真正的移动端拍照体验与账号体系（找回密码、审计日志）。

## 七、一页式项目介绍（可放 PPT 或海报）

**智膳 AI** · 全场景健康膳食管家

- **一句话**：拍一张包装或餐盘照片，完成识别、解释、健康画像约束与三餐方案。
- **三个能力**：多模态识别｜RAG 证据解释｜健康画像与智能配餐
- **三个可信**：原始文本保留可校正｜AI 结果标来源与可信度｜人工审核与审计可追溯
- **三个边界**：不做实验检测｜不判定添加剂“有毒”｜不构成医疗诊断
- **技术栈**：Vue 3 + TypeScript + Element Plus + ECharts｜Flask + SQLAlchemy + SQLite｜RapidOCR（本地）与 OpenAI 兼容大模型
- **交付物**：可运行的前后端源码、自动化测试、响应式截图、部署与演示文档

## 七、科普助手（加映 30 秒，可选）

如果评委对「AI 是不是只会读图」有疑问，加这一段：

> “除了看标签，我们还做了食安科普与辟谣助手。它用的是 RAG：先从知识库检索，
> 再组织答案，**没有检索到就不回答**，绝不编造。”

操作：

1. 打开「食安科普助手」；
2. 点热门问题「隔夜菜到底能不能吃？」→ 展示回答里的**结论 / 为什么 / 依据 / 来源**；
3. 点「西瓜和桃子一起吃会中毒吗？」→ 说明“食物相克”没有科学依据，来源来自膳食指南与辟谣平台；
4. 输入一个知识库没有的问题（例如“量子水能养生吗？”）→ 展示系统明确回复「未收录」，并给相近条目；
5. 收尾一句：“每句话都能点回来源，这是我们和通用聊天机器人最大的区别。”
